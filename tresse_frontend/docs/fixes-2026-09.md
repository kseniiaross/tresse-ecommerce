# Post-audit fixes — September 2026

## P1-02 — First-order promo code never shown

**What was broken:** `Order.tsx` checked order history by calling
`/orders/my-orders/`, but the backend route (`orders/urls.py`) is
`/orders/my/`. The request 404s, the catch block sets
`isFirstOrder(false)`, and the "15% off your first order" block with the
`TRESSE15` code never renders.

**Why it mattered to the customer:** The registration welcome email
promises new customers 15% off their first order with code `TRESSE15`,
but the order page never showed the promo, so first-time customers had
no way to see or use the discount they were told about.

**Files changed:**
- `src/view/Order.tsx`
- `src/view/Order.test.tsx`

**How to verify manually:**
1. Register a new account and open the order page before placing any
   paid order.
2. Confirm the "15% off your first order" block and `TRESSE15` code
   render.
3. Place and pay for an order, reload the order page, and confirm the
   promo block no longer renders.

## P0-11 — Session logged out ~30 minutes after login

**What was broken:** `refreshAccessToken` in `src/utils/axiosInstance.ts`
only read `resp.data.access` from `/accounts/token/refresh/`. The
backend has `ROTATE_REFRESH_TOKENS` and `BLACKLIST_AFTER_ROTATION`
enabled, so SimpleJWT returns a new access/refresh pair on every
refresh and blacklists the old refresh token. Since the frontend kept
reusing the now-blacklisted refresh token, the first refresh succeeded
and the second one failed, logging the user out.

**Why it mattered to the customer:** Sessions died roughly 30 minutes
after login regardless of activity, frequently interrupting customers
mid-checkout and forcing them to log in again to complete a purchase.

**Files changed:**
- `src/utils/axiosInstance.ts`

**How to verify manually:**
1. Log in.
2. Wait more than 30 minutes (long enough for at least one access
   token refresh cycle to occur).
3. Reload the page — the session must still be active, not logged out.
